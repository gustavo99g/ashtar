## Antes de distribuir a v0.2.0

- [x] **Trocar a key do LiveKit.** O secret da key atual apareceu numa conversa de suporte; apagar a key no
      painel, criar outra e atualizar o `.env` da API.
- [x] **Relógio do computador da API sincronizado.** O token é assinado com o `nbf` do relógio local; com o
      relógio ~1 minuto adiantado, o LiveKit Cloud recusou com "invalid token" (2026-10-06). Vale até a API ir
      para a VPS (v0.2.6). Alternativa no código: gerar o token com o `nbf` alguns segundos no passado.
- [x] **Avisar o grupo** que a v0.2.0 é instalada pelo `-setup.exe` e substitui o executável da v0.1, que
      pode ser apagado.

- [x] **Apagar o release `v0.1.92` do `ashtar-releases`**, publicado no teste do pipeline pela branch
      `teste/release`, e confirmar que o `beta/latest.json` passa a apontar para a 0.2.0 depois do merge.
- [x] **Renomear `master` para `main`** e passar a trabalhar por pull request (`dev` = beta, `main` =
      estável, decisão 3). O `origin/main` já existe; falta conferir que ele é o branch padrão de estável e
      aposentar o `master`.

## Riscos e cuidados

- [x] **Chave privada do updater** com cópia de segurança fora do GitHub (decisão 7). Sem ela, nenhuma
      atualização chega a quem já instalou.
- [x] **Minutos do GitHub Actions** (decisão 12): acompanhar o consumo do primeiro mês. Se apertar, rodar o
      job Windows só no release.
- [x] **`VITE_API_URL` no pipeline:** hoje a URL do Tailscale Funnel; quando a API mudar de endereço (v0.2.6),
      a variável do repositório muda e sai uma versão nova. O app instalado continua com a URL antiga até
      atualizar, então a URL antiga precisa responder até todos atualizarem.
- [x] **Versão mínima só depois de todos na v0.2.0** (decisão 8): ligar `MIN_CLIENT_VERSION` antes disso
      tira da sala quem ainda está na v0.1, sem mensagem clara.
- [x] **API sem proteção até `ACCESS_CODE` ser ligada:** quem descobrir a URL fixa do Funnel consegue
      tokens do LiveKit. Acompanhar o consumo no painel.
- [x] **Consumo de minutos do LiveKit Cloud:** se um mês passar de ~60% dos 5.000 minutos, o servidor
      (v0.2.6) passa à frente, ou o plano pago cobre o mês (gatilho no `docs/roadmap.md`).
- [x] **Token de publicação no `ashtar-releases`:** se for fine-grained, expira em no máximo um ano.
      Anotar aqui a data de expiração ao criá-lo; vencido, o pipeline para de publicar.
- [x] **Contrato da API durante o beta** (decisão 3): quem está no beta e o grupo usam a mesma API. Mudança
      de contrato sempre compatível com a versão anterior até a promoção.
- [x] **`ashtar-releases` precisa ter o branch `main` com ao menos um commit** (o pipeline cria as tags com
      `releaseCommitish: main`). Criar com um README antes da primeira publicação.
- [x] **Segredos do pipeline:** `RELEASES_TOKEN`, `TAURI_SIGNING_PRIVATE_KEY`, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`,
      `VITE_ACCESS_CODE` (secrets) e `VITE_API_URL` (variável) no repositório principal.
